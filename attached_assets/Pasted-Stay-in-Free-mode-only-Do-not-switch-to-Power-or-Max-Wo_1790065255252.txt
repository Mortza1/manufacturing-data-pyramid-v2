PART 1 — SAVE TO AN EXISTING PROJECT
1. Add an explicit Stage 5 save-target choice

In Review & Save, make the save destination clear.

Provide two choices:

Save to Existing Project

Save As New Project

Do not merge these into one ambiguous form.

2. Save to Existing Project

When Save to Existing Project is selected, show:

User

dropdown

followed by:

Project

dropdown

followed by:

Version Note (optional)

The Project dropdown must contain only projects belonging to the selected User.

Reuse the existing API:

GET /api/users/:userId/projects

Do not create another project-list endpoint.

3. User dropdown

Reuse the existing named users already stored in PostgreSQL.

When the selected User changes:

load that user's existing projects;
clear any previously selected Project;
do not accidentally retain a project belonging to another user.
4. Project dropdown

After a User is selected, list that user's saved projects.

For each project display at least:

project name;
optionally latest version number;
optionally short description where useful.

Sort sensibly, preferably most recently updated first.

Selecting the project should clearly establish:

This is the project whose next immutable version will be created.

Do not ask the user to type the existing project name manually.

5. Save New Version

Once an existing Project is selected, show:

Save New Version

The save operation must reuse the existing:

POST /api/projects/:projectId/versions

Send:

selected project ID in the route;
selected User ID as creatorUserId;
current complete Stage 5 snapshot;
optional Version Note.

Do not create a new API endpoint.

6. Version number remains server-controlled

The user does not select or type the new version number.

Continue the existing rule:

next version = highest existing version + 1

Example:

Project currently contains:

v1
v2
v3

Saving through Save to Existing Project produces:

v4

Existing historical versions remain immutable.

7. Support saving to an existing project even when it was not the loaded project

This is important.

The current working pyramid may:

have been created from scratch;
have been loaded from another project;
have been loaded from another version.

If the user deliberately selects:

User A → Project X → Save New Version

then append the current working snapshot to Project X.

Do not require Project X to be the project originally loaded into the Walkthrough.

The selected save destination is explicit and intentional.

8. Update working project context after successful save

Only after a successful and verified save:

update the loaded/current project context to the selected:

User ID/name;
Project ID/name;
newly created Version ID;
new version number;
latest version number.

The newly saved version becomes the current source version for subsequent Save New Version operations.

If the request fails:

do not change current project context;
do not change the local working case;
show the existing clear error state.
PART 2 — PRESERVE SAVE AS NEW PROJECT
9. Keep Save As New Project

Preserve the existing new-project path.

When selected, show:

User;
New Project Name;
Project Description;
Version Note.

Saving creates:

new Project ID → Version 1

using the existing:

POST /api/projects

Do not alter this currently working server flow.

10. Make the distinction obvious

Suggested explanatory text:

Save to Existing Project
Create the next version in an existing project history.

Save As New Project
Create a separate project starting at Version 1.

PART 4 — SAFETY
12. Preserve snapshot/version rules

Continue to use:

complete JSONB snapshots;
schemaVersion = 1;
server-side Zod/semantic validation;
immutable version rows;
unique (project_id, version_number);
transactional next-version creation;
Zustand as the local working draft.

Do not alter the persistence architecture.

13. Loading and errors

For the new project dropdown:

show appropriate:

error;
selected project state.

Disable Save New Version until:

User is selected;
Project is selected;
no save request is currently running.

Prevent duplicate submissions.
