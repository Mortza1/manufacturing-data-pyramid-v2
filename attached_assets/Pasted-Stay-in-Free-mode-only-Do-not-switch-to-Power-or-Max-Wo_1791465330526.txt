Confirmed cause
The manual Add Data dialog can reopen because Stage 2 can leave isDragging stuck as true when the dialog opens.
A grid-cell pointer-down starts dragging and opens the editor. The modal then intercepts the pointer release, so the grid never clears the drag state. After the modal closes, pointer-enter over the grid can trigger another placement and reopen the editor.
Successful Add also currently closes editorCell but leaves Add placement mode active.
Required fix
Use one shared manual-add close/reset path for both:
- Cancel / close
- successful Add Data submission
That reset must clear:
- the open editor cell;
- manual Add placement mode;
- the Stage 2 drag state.
Closing or completing the Manual Add dialog must therefore exit manual-add mode completely.
Also, when Add mode opens the manual editor from a grid pointer interaction, immediately clear the drag state so the pointer-down that opened the dialog cannot leave a latent drag behind the overlay.
Do not rely on a later grid pointer-up to clear it.
If appropriate, add a defensive pointer-cancel reset for the existing drag state, but do not redesign the placement interaction.

Add data manually → choose/place cell → dialog opens
