12. Version numbering rule

This is critical.

Never calculate the next version from the version currently opened.

Server-side, determine the project's current highest existing version number inside the save transaction.

Then:

next_version = highest_existing_version + 1

Example:

Existing:

v1
v2
v3
v4

User opens v1, edits it, then clicks Save New Version.

Result:

v5

not another v2.

13. Historical versions are immutable

Never update or overwrite an existing project_versions row during normal editing.

v1, v2, v3 etc. remain permanently retrievable.

Saving edits always appends another immutable snapshot.

14. Save transaction

Saving a new version should happen atomically:

confirm project exists;
confirm selected project/user relationship;
determine current maximum version number inside the transaction;
validate current activeCase;
create complete snapshot;
insert new immutable version;
update projects.current_version_id;
update project timestamp;
commit.

Preserve the unique constraint on:

(project_id, version_number)

Handle any concurrency conflict safely rather than overwriting.
